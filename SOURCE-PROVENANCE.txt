================================================================================
CORRESPONDING SOURCE FOR BUNDLED GPL COMPONENTS
================================================================================

This file exists to satisfy the source-availability obligation of the GPL for
third-party components distributed in binary form inside this project's
artifacts (GPLv3 section 6(d)).  It records exactly which upstream versions
those binaries were built from and where their source is published.

Last verified: 2026-09-14


--------------------------------------------------------------------------------
1. HOW THESE BINARIES GOT HERE
--------------------------------------------------------------------------------

This project does NOT compile FFmpeg or any codec library.  It installs the
PyAV Python package, whose binary wheels ship pre-compiled FFmpeg libraries
built by the PyAV maintainers.  Those libraries are then copied into the
frozen sidecar executable by PyInstaller.

    PyAV wheel                av == 18.1.0   (pinned in requirements*.txt)
      pins ->                 PyAV-Org/pyav-ffmpeg release tag "8.1.2-1"
        (per PyAV scripts/ffmpeg-8.1.json:
         https://github.com/PyAV-Org/PyAV/blob/v18.1.0/scripts/ffmpeg-8.1.json
         -> https://github.com/PyAV-Org/pyav-ffmpeg/releases/download/8.1.2-1/ffmpeg-{platform}.tar.gz)
      which builds ->         the upstream sources listed in section 3

Build recipe for the binaries actually shipped (this is the "scripts used to
control compilation" for the bundled libraries).  Component versions, source
URLs and checksums are in pkg.py; configure flags per platform in
build-ffmpeg.py:

    https://github.com/PyAV-Org/pyav-ffmpeg/tree/8.1.2-1
    https://github.com/PyAV-Org/pyav-ffmpeg/blob/8.1.2-1/scripts/pkg.py
    https://github.com/PyAV-Org/pyav-ffmpeg/blob/8.1.2-1/scripts/build-ffmpeg.py

Everything below was read from the recipe at that tag and cross-checked against
the PyAV 18.1.0 wheels this project ships from: manylinux_2_28_x86_64 (Linux),
win_amd64 (Windows) and macosx_14_0_arm64 (macOS).

2. WHAT IS ACTUALLY SHIPPED
--------------------------------------------------------------------------------

Library versions as reported by the shipped binary itself (av.library_versions,
identical on all three platforms):

    libavcodec      62.28.102
    libavdevice     62.3.102
    libavfilter     11.14.102
    libavformat     62.12.102
    libavutil       60.26.102
    libswresample   6.3.102
    libswscale      9.5.102

    -> FFmpeg 8.1.2  (av.ffmpeg_version_info)

FFmpeg configure string, read verbatim out of each platform's shipped avutil
binary.  Common to all three:

    --disable-static --enable-shared --disable-programs --disable-doc
    --disable-libxml2 --disable-lzma --disable-libtheora --disable-libfreetype
    --disable-libfontconfig --disable-libbluray --disable-libopenjpeg
    --enable-version3 --enable-libdav1d --enable-libmp3lame
    --enable-libopencore-amrnb --enable-libopencore-amrwb --enable-libopus
    --enable-libsvtav1 --enable-libvpx --enable-libwebp --enable-zlib
    --enable-libx264 --enable-libx265
    --disable-encoder='avui,dca,mlp,opus,s302m,sonic,sonic_ls,truehd'
    --disable-decoder=sonic --disable-libjack --disable-indev=jack
    --disable-filter=gfxcapture

Per platform, in addition:

    Linux x86-64   --libdir=/tmp/vendor/lib --prefix=/tmp/vendor
                   --disable-mediafoundation --enable-alsa --enable-gnutls
                   --enable-libxcb --enable-nvenc --enable-nvdec --enable-amf
                   --enable-libvpl
    Windows x86-64 --libdir=/c/cibw/vendor/lib --prefix=/c/cibw/vendor
                   --enable-mediafoundation --disable-alsa --disable-gnutls
                   --disable-libxcb --enable-nvenc --enable-nvdec --enable-amf
                   --enable-libvpl
    macOS arm64    --libdir=/tmp/vendor/lib --prefix=/tmp/vendor
                   --disable-mediafoundation --disable-alsa --disable-gnutls
                   --disable-libxcb --enable-videotoolbox --enable-audiotoolbox
                   --extra-ldflags='-Wl,-ld_classic'

NOTE ON AN INCONSISTENCY: the literal flag "--enable-gpl" does not appear in
any of these strings, yet "--enable-libx264" and "--enable-libx265" do -- a
combination FFmpeg's own configure normally rejects.  The cause could not be
determined from the shipped binaries.  It does not change this project's
obligations: x264 and x265 are GPL-2.0-or-later projects in their own right,
and their compiled libraries are distributed here, so GPL terms apply to them
regardless of how FFmpeg itself was configured.

Shared libraries bundled with PyAV, per platform (from the wheels):

    all            FFmpeg (the seven libraries above), dav1d, LAME, opencore-amr
                   (amrnb, amrwb), Opus, SVT-AV1 (encoder), libvpx, libwebp
                   (with libsharpyuv, libwebpmux), x264, x265
    Linux only     GnuTLS, GMP, nettle (libnettle, libhogweed), libunistring,
                   alsa-lib (libasound), libvpl, and -- copied in from the
                   manylinux_2_28 build image, not built by the recipe --
                   libdrm, libXau, libxcb, libxcb-shape, libxcb-shm,
                   libxcb-xfixes
    Windows only   libvpl, zlib 1.3.2, GNU libiconv 1.19, and the MSYS2
                   mingw-w64 GCC 16.1.0 runtime (libgcc_s_seh, libstdc++,
                   libwinpthread)

The recipe also builds libpng 1.6.58, but no shipped library contains it, and
the AMF and NVIDIA codec headers (Linux, Windows) are compiled into FFmpeg
rather than shipped as libraries.

4. MAINTENANCE
--------------------------------------------------------------------------------

This file is part of how this project stays compliant, not a one-time note.

  * It ships inside every distributed artifact, next to THIRD-PARTY-LICENSES.txt,
    and each release's notes link to it at that release's tag.
  * Every URL above must resolve before publishing a release; the release
    workflow's preflight checks this and fails the release otherwise.
  * If a URL stops resolving while the artifact is still offered, the directions
    must be corrected or the source rehosted -- the obligation does not transfer
    to the upstream host.
  * PyAV is pinned to one exact version (av==18.1.0 in requirements.txt,
    requirements-linux.txt and requirements-macos.txt), and the release
    workflow's preflight fails any build whose pin differs from the "av =="
    version recorded in section 1.  Bumping PyAV therefore means re-deriving
    EVERYTHING above: read the new PyAV scripts/ffmpeg-*.json for the new
    pyav-ffmpeg tag, that tag's scripts/pkg.py and build-ffmpeg.py for the new
    component versions and flags, and the new wheels for what actually ships.
