================================================================================
CORRESPONDING SOURCE FOR BUNDLED GPL COMPONENTS
================================================================================

This file exists to satisfy the source-availability obligation of the GPL for
third-party components distributed in binary form inside this project's
artifacts (GPLv3 section 6(d)).  It records exactly which upstream versions
those binaries were built from and where their source is published.

Last verified: 2026-09-08


--------------------------------------------------------------------------------
1. HOW THESE BINARIES GOT HERE
--------------------------------------------------------------------------------

This project does NOT compile FFmpeg or any codec library.  It installs the
PyAV Python package, whose binary wheels ship pre-compiled FFmpeg libraries
built by the PyAV maintainers.  Those libraries are then copied into the
frozen sidecar executable by PyInstaller.

    PyAV wheel                av == 16.0.1
      pins ->                 PyAV-Org/pyav-ffmpeg release tag "8.0-2"
        (per PyAV scripts/ffmpeg-8.0.json:
         https://github.com/PyAV-Org/pyav-ffmpeg/releases/download/8.0-2/ffmpeg-{platform}.tar.gz)
      which builds ->         the upstream sources listed in section 3

Build recipe for the binaries actually shipped (this is the "scripts used to
control compilation" for the bundled libraries):

    https://github.com/PyAV-Org/pyav-ffmpeg/tree/8.0-2
    https://raw.githubusercontent.com/PyAV-Org/pyav-ffmpeg/8.0-2/scripts/build-ffmpeg.py

2. WHAT IS ACTUALLY SHIPPED
--------------------------------------------------------------------------------

Library versions as reported by the shipped binary itself (av.library_versions):

    libavcodec      62.11.100
    libavdevice     62.1.100
    libavfilter     11.4.100
    libavformat     62.3.100
    libavutil       60.8.100
    libswresample   6.1.100
    libswscale      9.1.100

    -> FFmpeg 8.0.x

FFmpeg configure string, read verbatim out of the shipped avutil binary:

    --disable-static --enable-shared --libdir=/c/cibw/vendor/lib
    --prefix=/c/cibw/vendor --disable-programs --disable-doc --disable-libxml2
    --disable-lzma --disable-libtheora --disable-libfreetype
    --disable-libfontconfig --disable-libbluray --disable-libopenjpeg
    --enable-mediafoundation --enable-version3 --enable-gmp --disable-alsa
    --disable-gnutls --enable-libaom --enable-libdav1d --enable-libmp3lame
    --enable-libopencore-amrnb --enable-libopencore-amrwb --enable-libopus
    --enable-libspeex --enable-libsvtav1 --enable-libtwolame --enable-libvorbis
    --enable-libvpx --enable-libwebp --enable-libopenh264 --disable-libxcb
    --enable-zlib --enable-libx264 --enable-libx265 --enable-nvenc
    --enable-nvdec
    --disable-encoder='avui,dca,mlp,opus,s302m,sonic,sonic_ls,truehd,vorbis'
    --disable-decoder=sonic --disable-libjack --disable-indev=jack

NOTE ON AN INCONSISTENCY: the literal flag "--enable-gpl" does not appear in
that string, yet "--enable-libx264" and "--enable-libx265" do -- a combination
FFmpeg's own configure normally rejects.  The cause could not be determined
from the shipped binary.  It does not change this project's obligations: x264
and x265 are GPL-2.0-or-later projects in their own right, and their compiled
libraries are distributed here, so GPL terms apply to them regardless of how
FFmpeg itself was configured.

--------------------------------------------------------------------------------
4. MAINTENANCE
--------------------------------------------------------------------------------

This file is part of how this project stays compliant, not a one-time note.

  * It ships inside every distributed artifact, next to THIRD-PARTY-LICENSES.txt.
  * Every URL above must be confirmed to resolve before publishing a release.
  * If a URL stops resolving while the artifact is still offered, the directions
    must be corrected or the source rehosted -- the obligation does not transfer
    to the upstream host.
  * If the pinned PyAV version changes, EVERYTHING above must be re-derived:
    read the new PyAV scripts/ffmpeg-*.json to find the new pyav-ffmpeg tag,
    then that tag's build recipe for the new component versions.
