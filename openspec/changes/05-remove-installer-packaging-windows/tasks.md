## 2. Windows verification (moved from `remove-installer-packaging`)

- [x] 2.0 (real bug found during user testing, not in original plan) Fix `resolve_model_dir()`'s incomplete Windows extended-length-path handling

  **Real bug, found and fixed, then confirmed by the user.** User testing (running `transcriber-gui.exe` from `dist/portable/Transcriber/` via its `\\wsl.localhost\...` UNC path) hit `FileNotFoundError: --model-path UNC\wsl.localhost\...\model does not exist` on file transcription. Root cause: `resolve_model_dir()` already stripped Windows' `\\?\C:\...` extended-length prefix (an earlier ctranslate2 fix) but not the UNC form, `\\?\UNC\server\share\...` — stripping only `\\?\` from that form leaves the literal text `UNC\server\share\...`, not a valid path. Fixed in `src-tauri/src/sidecar.rs`: extracted the stripping logic into a pure `strip_extended_length_prefix()` helper handling both forms, added 3 unit tests (local-drive prefix, UNC prefix — using the exact string from the real error — and passthrough for already-plain/non-Windows paths), all passing (`cargo test sidecar::tests`). Rebuilt and reassembled `dist/portable/Transcriber.zip`. **Confirmed fixed**: file transcription works after a full app restart (the first retest reproduced the identical error because the old process was still running in memory — same file on disk, stale in-process code; closing and relaunching resolved it).
- [x] 2.0b (found during the same retest) Add a "Stopping…" UI indicator for live capture

  **Real, minor UX gap, found and fixed.** After 2.0's fix, live capture started correctly (banner/status lines confirmed in the debug log, UI showed active/listening), but clicking Stop gave no visible feedback. Traced it: no `stopping` state indicator existed at all in the frontend (only `starting-stamp`/`live-stamp`) — the transition from active→idle on stop happens almost instantly with nothing shown in between, so it looked like nothing happened even though the stop command itself was working. Added a `stopping-stamp` element (`src/index.html`, `src/main.js`), reusing the existing `stamp-starting` CSS class (visually identical "in progress" style, no new CSS needed) and wiring it into both `setLiveState()` and `updateTopline()` matching the exact pattern the `starting`/`live` stamps already use. Rebuilt, reassembled the zip.
