  **First attempt 2026-09-11, by the user on Fedora 44/KDE, with the CI-built `.rpm` from the `v0.1.0` draft.** It installed, the GUI ran, and a dropped file transcribed. The package has since been removed (`rpm -q transcriber` reports "not installed"). Four problems found; this task stays open until the packaging ones are fixed and re-tested:
  1. **The file and install names start with a capital T** (`Transcriber-0.1.0-1.x86_64.rpm`, `/usr/lib/Transcriber`, `Transcriber.desktop`). The package *name* is already lowercase (`transcriber`); the capital comes from `productName`. Packaging.
  2. **Dropping a second file while one is transcribing starts another run.** `transcribeFile()` in `src/main.js` sets `fileBusy` but never checks it, and `start_file_transcription` in `sidecar.rs` spawns an untracked sidecar on every call. The only busy sign is a small "Transcribing" dot below the format controls; the drop zone doesn't change. A GUI bug that predates this change.
  3. **The app doesn't appear in KDE's application search.** The packaged `.desktop` file is valid, but its `Categories=` is empty, because `bundle.category` isn't set. `kbuildsycoca6 --menutest`, run against a scratch `XDG_DATA_HOME` holding the packaged entry, files it under `Lost & Found/`; with `Categories=Utility;` it goes to `Utilities/`. Tauri maps `bundle.category: "Utility"` to exactly that. Packaging. Also, only a 32×32 icon ships (`src-tauri/icons/icon.png`), so launchers will show it blurry.
  4. **GUI live capture fails on Linux:** `❌ --wasapi is only supported on Windows`. `build_live_session_args()` in `sidecar.rs` always passes `--wasapi`; its own `ponytail:` note recorded that as a known shortcut, reachable because only macOS gates the live tab. GUI live capture has never worked on Linux. A GUI bug that predates this change.
